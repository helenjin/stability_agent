% --- Findings, confirmed on the full 24-recipe sample ---
%
% - TopoDev/TopoVar: stable across n=5/18/24 -- SAGER (either variant) cuts
%   TopoDev roughly in half relative to ARES (0.128 -> 0.065-0.067) and
%   TopoVar by ~5x. Parents vs. ancestors remain statistically
%   indistinguishable on this metric at every sample size checked.
%
% - F1: the ARES-vs-SAGER gap, which widened from n=5 to n=18, STABILIZED
%   rather than continuing to widen: error-class F1 gap (SAGER minus ARES)
%   was 0.305/0.217 (parents/ancestors) at n=5, 0.327/0.273 at n=18, and is
%   0.321/0.291 at n=24 -- this answers the open question left in the n=18
%   notes ("worth watching whether it keeps widening or stabilizes").
%
% - A genuine, now-confirmed tradeoff between the two SAGER variants: direct
%   parents (SAGER) has higher raw F1 (0.653 vs. 0.623), while the full
%   ancestor closure (SAGER-ancestors) is slightly more order-STABLE (Delta
%   F1 0.081 vs. 0.095; Jaccard 0.925 vs. 0.916). Consistent with the
%   intuition that more upstream context helps overall detection accuracy
%   less than it helps invariance to which valid ordering is shown -- ARES's
%   full prefix has even more context than either SAGER variant, and is both
%   the least accurate (F1 0.332) and least order-stable (Delta F1 0.205,
%   Jaccard 0.673) of the three, so "more context" alone does not explain
%   the SAGER-vs-ARES gap -- the graph-conditioning (vs. sequence-prefix
%   conditioning) is doing the real work.
%
% - ARES is now below BOTH SAGER variants on every single column in the
%   Macro-F1 table, including sound-class F1 (0.399 vs. 0.515/0.470) -- this
%   trend first appeared at n=18 and holds at the full n=24.
%
% - CORRECTION (was wrong in an earlier draft of this file): there is no
%   paper Macro-F1 number for Qwen2.5-7B-Instruct to compare against -- the
%   paper never evaluates that backbone (only GPT-4o-mini and, in this
%   project's own still-unrun Table 1 plan, Qwen3-4B -- a different, newer,
%   smaller model; see table1_valid_reordering.tex). 0.633 is a GPT-4o-mini
%   number and has no bearing on what ARES "should" score here. Framing
%   this Qwen run's absolute Macro-F1 (0.493 -> 0.379 -> 0.366 across
%   n=5/18/24) as a "gap vs. the paper that stabilized" was a mistake:
%   there was never a reason to expect convergence toward an unrelated
%   backbone's number. The one valid cross-check remains that THIS SAME
%   pipeline, run on GPT-4o-mini instead of Qwen, lands within 0.05 of the
%   paper's 0.633 (table5_macro_f1_comparison.tex, 0.583) -- confirming the
%   harness itself is sound, and that the low absolute number here is a
%   real Qwen2.5-7B-Instruct backbone-weakness effect, not evidence about
%   how close or far this run is from "the paper's" result.
%
% - mean_exact_match_rate is 0.0 for all three methods across all 24
%   recipes: no method, on any recipe, ever predicts the identical error set
%   across all 10 sampled orderings. This looks like a structural property
%   of K=10 sampled orderings on graphs this size/branchiness, not a
%   small-n artifact -- worth stating as a property of the setup rather than
%   a point of comparison between methods.
