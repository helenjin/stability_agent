- **H1** (parametric more stable "on static domains") overclaims: the "static domains" qualifier has never actually been tested against a dynamic-domain comparison. What's shown so far is just "parametric > retrieved on average," not the moderator.
- **H2** (retrieval helps on dynamic/long-tail/conflict-heavy tasks) bundles three separable claims mapped to three different future datasets (FreshQA, PopQA, ConflictBank) that could disagree with each other. Should be split into H2a/H2b/H2c before results come in.
- **H4** (source sensitivity is example-dependent) is nearly unfalsifiable as written — any noisy per-example metric shows non-uniform gaps. S5 (instability scales with claim count, not redundancy) is a sharper, real H4-shaped hypothesis and should replace the generic framing.

## H5 test — method and results

Extremity := `|true_label|` (SciFy, per-source judge base label, scale −2..+2) or `|likert|` (ScholarQA, scale −2..+2). Tested against three already-cached datasets, no new API calls:
`reports/source_comparison_balanced.json` (106 × 3 sources), `reports/scholar_stability_uncapped.json` (n=62), `reports/scholar_stability_dataset.json` (n=41, size-controlled). Script: session scratchpad `test_h5.py` (not yet committed to the repo).

**SciFy** — cross-source gap shrinks with extremity: mean gap 0.688 → 0.634 → 0.467 across extremity 0/1/2 (spearman −0.32). Within-source, extremity strongly predicts parametric's own stability (+0.54) but barely predicts retrieved sources' (+0.13 `all`, −0.00 `nonweb`). Confound check: extremity vs. pool size only +0.16, so this isn't a perturbation-budget artifact.

**ScholarQA (size-controlled, n=41)** — same direction: `|delta|` vs. `|likert|` = −0.27, smallest gap at the extreme bin (0.185 at `|likert|=2` vs. 0.342–0.376 elsewhere). **ScholarQA (uncapped, n=62)** is flatter/noisier (−0.08) — no clean pattern at natural sizes.

**Twist:** retrieved sources actually have *more* extreme true_labels on average than parametric (73% at `|label|=2` vs. 41% for parametric), yet are still far less stable — so extremity does not explain away the H1 gap; it's a real but source-specific secondary effect, strongest within parametric.

**Verdict:** H5 partially supported. Real effect (~30% gap reduction at extremes), not the near-elimination a strong reading would predict, and noisy at the low-extremity tails (n=2–4 in some bins). Best used as a control variable in future analyses (e.g. stratifying H8) rather than a standalone result.

## Correction — the ClaimSpy domain/quality join was against the wrong corpus

Looking more closely at H3 surfaced a bigger problem: `load_claimspy_metadata` (`stability_agent/datasets/claimspy.py`) joins stability-run index `di` to the `di`-th sorted file in `claimspy_v1_ICL_Agent_2`. But the stability runs (`ss_rate_dicts_all*`) are generated by `SciFyDataset` (`mythbusters/src/exp_helpers/datasets/scify.py`) iterating a *different* corpus entirely: `data/scify/v1/system-outputs-dry-run-&-potluck/potluck-dry-run-raw-outputs/<problem_id>/ICL-agent-1-000.json`, in potluck-dry-run problem-list order. `claimspy_v1` (IDs like `alloys_0001`) and the potluck set (IDs like `matsci_db_001`, `jhu-alloys-0008`) share zero problem IDs — they're disjoint corpora that happen to share the same JSON schema. Verified via 103/106 exact match between each problem's own `ICL-agent-1-000.json` likert_score and the parametric run's stored `true_label`, joined in potluck order.

This invalidated every domain label and named example from this session's ClaimSpy analysis (H4's example list, `claimspy_gap_audit_systematic.md`'s domain table) — `alloys`/`computational_tools`/`superconductors` etc. aren't real domains in the true corpus; the real domains are lab/provenance tags (`jhu-alloys-*`, `matsci_db`, `str_speculative`, `umbc_*`, `gtri`, `mof_*`, `vis_reas_*`).

**Fixed**, in `stability_agent/datasets/scify_index.py`:
1. `build_index_map` used to glob every `*.json` in a problem's folder and keep whichever sorted last alphabetically — some problems have multiple system outputs (e.g. `PoVE-multiagent.json` alongside `ICL-agent-1-000.json`), so it silently picked the wrong one for `matsci_db_001` (likert −1 instead of the correct −2). Now reads `<assessment_dir>/<problem_id>/ICL-agent-1-000.json` directly.
2. Added `load_scify_index_metadata(eval_data_dir, assessment_dir)`, a drop-in replacement for `load_claimspy_metadata` (same output shape, keyed by `str(di)`), sourced from the correct corpus.
3. Registered the correct corpus as `scify_potluck_raw` in `data/registry.yaml` (symlink added to `scripts/setup_data.sh`), with notes on both `claimspy_v1` and `stability_runs` warning against the old join.
4. Extended `stability_agent/reporting/claimspy_summary.py` with `build_gap_audit`/`render_gap_audit_markdown` (the systematic gap audit was previously an uncommitted one-off script) and regenerated `claimspy_followup_summary.{json,md}` and `claimspy_gap_audit_systematic.{json,md}` via `scripts/regenerate_claimspy_reports.py`.
